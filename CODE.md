# Code Walkthrough

How the ESP32 plays a song animation on the SSD1306 OLED, and how the Python tools create new ones.

[← Back to main README](README.md)

## Project structure
```
esp32_oled_animations/
├── radhima/
│   ├── radhima.ino      # Arduino sketch (display + playback logic)
│   └── animation.h      # Frame data + delays (auto-generated)
├── rathinamo/ ...       # same two files per song
├── gif_to_oled.py       # GIF -> animation.h + .ino
├── lyrics_to_gif.py     # lyrics text -> GIF
└── README.md
```
Every song folder has the same two files. Only `animation.h` changes between songs.

## 1. The Arduino sketch (`.ino`)

### Libraries and display setup
```cpp
#include <Wire.h>
#include <Adafruit_GFX.h>
#include <Adafruit_SSD1306.h>
#include "animation.h"

#define SCREEN_WIDTH 128
#define SCREEN_HEIGHT 64

Adafruit_SSD1306 display(SCREEN_WIDTH, SCREEN_HEIGHT, &Wire, -1);
```
- `Wire.h` is the I2C library (ESP32 default pins: SDA = GPIO 21, SCL = GPIO 22).
- `Adafruit_GFX` provides drawing functions, and `Adafruit_SSD1306` is the driver for the display chip.
- `-1` means the OLED has no separate reset pin.
- `animation.h` holds the frames and is generated by the Python tool.

### `setup()`
```cpp
void setup() {
  display.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  display.clearDisplay();
}
```
- `0x3C` is the I2C address of most 0.96" OLEDs.
- `SSD1306_SWITCHCAPVCC` makes the display generate its own high voltage from 3.3 V.

### `loop()`
```cpp
void loop() {
  playGIF(&Radhima_gif);
}
```
The animation plays once per call, and `loop()` repeats it forever.

### `playGIF()`: the main function
```cpp
void playGIF(const AnimatedGIF* gif) {
  for (uint16_t frame = 0; frame < gif->frame_count; frame++) {
    display.clearDisplay();

    for (uint16_t y = 0; y < gif->height; y++) {
      for (uint16_t x = 0; x < gif->width; x++) {
        uint16_t byteIndex = y * ((gif->width + 7) / 8) + (x / 8);
        uint8_t  bitIndex  = 7 - (x % 8);
        uint8_t  b = pgm_read_byte(&(gif->frames[frame][byteIndex]));

        if (b & (1 << bitIndex)) {
          display.drawPixel(x, y, SSD1306_WHITE);
        }
      }
    }

    display.display();
    delay(gif->delays[frame]);
  }
}
```
Step by step:
1. Loop over every frame.
2. Clear the screen buffer.
3. For each pixel `(x, y)`, find which byte holds it. Each row is 16 bytes (128 ÷ 8), so `byteIndex = y * 16 + x / 8`.
4. Find which bit in that byte is the pixel. The bits are stored MSB first, so `bitIndex = 7 - (x % 8)`.
5. Read the byte from flash with `pgm_read_byte()`, because the data is in PROGMEM and not in RAM.
6. If the bit is 1, draw a white pixel.
7. `display.display()` sends the buffer to the OLED over I2C.
8. Wait for this frame's delay, then continue to the next.

## 2. The data file (`animation.h`)

### The data structure
```cpp
typedef struct {
  const uint8_t   frame_count;
  const uint16_t  width;
  const uint16_t  height;
  const uint16_t* delays;
  const uint8_t (* frames)[1024];
} AnimatedGIF;
```
One struct describes a whole animation, which is why a single `playGIF()` works for every song.

> `frame_count` is a `uint8_t`, so one animation can have at most **255 frames**.

### The frames
```cpp
PROGMEM const uint8_t Song_frames[FRAME_COUNT][1024] = { ... };
```
- A 128×64 black-and-white frame is 128 × 64 ÷ 8 = **1024 bytes**.
- `PROGMEM` keeps the data in flash memory, so the ESP32's RAM stays free for other things.
- Example: 222 frames × 1024 bytes ≈ 222 KB of flash.

### The delays
```cpp
const uint16_t Song_delays[FRAME_COUNT] = {100, 100, ...};
```
Milliseconds each frame stays on screen. Different delays per frame let you hold a lyric line longer.

## 3. `gif_to_oled.py`: GIF to Arduino code

```
python gif_to_oled.py song.gif SongName --template radhima/radhima.ino
```
What it does:
1. **Loads every GIF frame** with Pillow (`ImageSequence`).
2. **Fits the frame to 128×64**, keeping the aspect ratio and adding black bars (`ImageOps.contain`).
3. **Converts to 1-bit**, using a brightness threshold, or dithering with `--dither`.
4. **Packs pixels into bytes.** Eight pixels go into one byte, with the leftmost pixel as the highest bit, row by row.
5. **Reads each frame's duration** from the GIF and stores it as the delay.
6. **Writes `animation.h`** with the struct, frames and delays, using the song name for the variable names.
7. **Writes the `.ino`** by copying your template sketch and changing the `playGIF(&...)` call.

| Option | Effect |
|---|---|
| `--threshold N` | Brightness cut-off (0–255) |
| `--dither` | Shaded look instead of plain black and white |
| `--invert` | Swap black and white |
| `--step N` | Keep every Nth frame (fewer frames, smaller size) |
| `--delay N` | Force the same delay for every frame |

## 4. `lyrics_to_gif.py`: lyrics to GIF

```
python lyrics_to_gif.py lyrics.txt song.gif --image art.png
```
1. Reads your lyrics file, one line per line.
2. Reveals each line **word by word**, wrapping the text to fit the screen.
3. Optionally shows an image on the right side.
4. Holds the finished line for a moment (`--hold-ms`).
5. Saves everything as a GIF with per-frame timing, ready for `gif_to_oled.py`.

|---|---|
| One frame | 1024 bytes |
